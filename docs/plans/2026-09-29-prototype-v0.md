## 1. Песочница движения + спайк проекции — готово

GDD §3, §4. Одна пустая комната (прямоугольник → отрезки стен, коллизия по 2D-геометрии).

План реализации (2026-09-29):

1. **Ввод.** `Command = { type: 'press', button }`, кнопки `forward/back/left/right/dash`; `InputState.held` (зажатые кнопки) и `InputState.look` (yaw/pitch). Клавиатура: WASD и стрелки, `Space` = dash (для фазы 3, пока не используется). `core/input/mouseLook.ts`: Pointer Lock по клику (`unadjustedMovement`, если браузер даёт), `movementX/Y` → yaw/pitch сразу в обработчике события, pitch в пределах `PITCH_LIMIT`. Тач, свайпы, защита жестов, PWA-манифест и мобильные meta — удалить.
2. **Геометрия.** `sim/level/geometry.ts`: `Rect`, `Segment`, `rectWalls()`, ближайшая точка на отрезке. `sim/level/sandbox.ts`: комната `sandbox.ROOM_W × ROOM_D` плюс колонны и внутренняя стена с проёмом — чтобы проверить скольжение, углы и читаемость проёма. Высоты — только данные для рендера.
3. **Движение** (`sim/player.ts`): желаемая скорость из held-кнопок и yaw, диагональ нормализована; скорость стремится к цели с `ACCEL` (есть ввод) или гасится `FRICTION` (нет ввода). Коллизия круг↔отрезки: перемещение делится на подшаги не длиннее `SUBSTEP`, после каждого — выталкивание из стен и удаление составляющей скорости в стену (скольжение). Хранится прошлая позиция для интерполяции рендера.
4. **World:** демо (пипы, сетка, счёт) удаляется; `StepInput = { commands, held, yaw }`; события — через `SimEvent`.
5. **Рендер.** `render/levelMesh.ts`: пол/потолок/стены, нарезанные на сегменты `view.MESH_SEGMENT` (~1 м, нужно для vertexFisheye), плоские цвета в вершинах, шахматка на полу для чувства скорости, `MeshBasicMaterial` + туман, без света. Туман радиальный (по расстоянию, не по глубине) — иначе при широком FOV края светлеют.
6. **Проекции** (`render/camera/`): интерфейс `Projection` (`render`, `resize`, `halfFovH` — порог для rear vision §12). `perspective` — вертикальный FOV из `H_FOV` и аспекта. `cubemap` — `CubeCamera` с гранями `CUBE_FACE_SIZE` + полноэкранный шейдер: пиксель → угол (equidistant / stereographic, `FISHEYE_MAPPING`) → направление → выборка из куба. `vertexFisheye` — патч `project_vertex` всех материалов через `onBeforeCompile`, общий uniform-флаг, без перекомпиляции при переключении. Для fisheye-режимов свой `FISHEYE_H_FOV` (180), чтобы сравнивать каждый режим на его естественном обзоре. Чистая математика — в `fisheyeMath.ts`, с тестами.
7. **Разрешение.** Канвас рендерится в `INTERNAL_SCALE` от окна, растягивается CSS `image-rendering: pixelated`; `MAX_PIXEL_RATIO` = 1.
8. **Отладка.** Выпадающие списки для строковых тюнингов (`OPTIONS` в `tuningLayout.ts`), клавиша `P` при открытом DBG переключает проекцию, оверлей: проекция, скорость, позиция. `__game.input.held/look` — управление без Pointer Lock.
9. **Тесты:** разгон/торможение по тикам из тюнинга, диагональ, направление по yaw, стена не пробивается ни на какой скорости, скольжение вдоль стены, колонна, пауза, математика проекций.
10. **Спайк:** сравнить три режима в Chrome (1920×1080), записать FPS и впечатления в VISUAL.md §3 и сюда; выбор проекции — вместе с пользователем после плейтеста. Потом удалить проигравшие режимы.

## 2. Тестовый уровень из фиксированного графа — в работе

GDD §2, §8, §10, §14. Фиксированный граф в коде (`sim/level/fixed.ts`) через настоящий `build.ts`: прямоугольники комнат/коридоров → стены с проёмами.

План реализации (2026-09-29):

1. **Данные уровня.** `sim/level/graph.ts` — граф на сетке (`rooms` с клетками, `edges`, `start`, `eye`, `route` — дуга зелёной линии задаётся явно, генератор фазы 6 будет её выбирать). `layout.ts` — прямоугольники комнат с высотами и коридоры (ширина, высота). `fixed.ts` — большая петля из 6 комнат (START → 3 комнаты до EYE, вторая дуга из 3 комнат назад) плюс боковая комната; коридоры разной ширины и длины, один длинный через клетку.
2. **Сборка** (`build.ts`, Layout → Level): прямые коридоры между комнатами (L-повороты — фаза 7); стороны комнат минус проёмы → отрезки стен; над проёмами перемычки (коридор ниже комнаты); стены коридоров. Стена START — сторона START-комнаты без проёмов, самая дальняя от первого проёма маршрута; спавн в `SPAWN_DISTANCE` от неё лицом к проёму. Маршрут: центр комнаты → проём → проём → центр → … → EYE. Песочница фазы 1 удаляется.
3. **Забег** (`World`): состояния `TITLE / PLAYING / LEVEL_CLEAR / DEAD / PAUSED`, фазы `INWARD / ESCAPE`. Касание EYE (круг `eye.RADIUS`) в INWARD → ESCAPE; касание белой стены в ESCAPE → LEVEL_CLEAR на `LEVEL_CLEAR_TIME` → следующий уровень (пока тот же фиксированный). Статистика забега (§14.2). `stateTicks` не идут в паузе. `kill()` — для врага фазы 4, пока только из debug; `god` защищает. Рестарт после `DEATH_COLLAPSE_TIME + RESTART_LOCKOUT` по клику или `Space`, новый забег — новый сид.
4. **Ввод:** команды `confirm` (клик), `pause` (Pointer Lock потерян), `resume` (Pointer Lock получен) — пауза снимается только с возвратом мыши.
5. **Рендер:** уровень из `Level` (зоны пола/потолка с разными высотами, грани стен, белая стена START), `render/actors.ts` — EYE (сфера, зрачок, зелёное кольцо, вращение) и зелёная линия (лента над полом, нарезана для fisheye); обе без тумана, исчезают сразу в ESCAPE.
6. **UI** (`src/ui/`): титул с лучшим результатом, HUD (EYES, время, пометка ESCAPE), экран уровня `EYE 07 / ESCAPE 12.48 / TOTAL 02:41.22`, пауза, смерть (вспышка → коллапс экрана → результат → рестарт). Все строки — `t()`. `RunResult` и лучший результат — `localStorage`.
7. **Звук** (`src/audio/`): синтез WebAudio — старт, подбор EYE, выход, смерть.
8. **Тесты:** инварианты сборки (маршрут не пересекает стены, у стены START нет проёмов, спавн внутри), переходы состояний, пауза, рестарт с защитой, бот, проходящий маршрут до EYE и обратно.

Ход работ (2026-09-29): пункты 1–8 сделаны, 39 тестов и сборка зелёные. В браузере проверено: титул, линия и EYE, подбор (EYE и линия исчезают, HUD «ESCAPE»), белая стена, экран уровня, смерть (вспышка → коллапс → результат), рестарт через клик, лучший результат в `localStorage`.
