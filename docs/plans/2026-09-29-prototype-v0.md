## 1. Песочница движения + спайк проекции — готово

GDD §3, §4. Одна пустая комната (прямоугольник → отрезки стен, коллизия по 2D-геометрии).

План реализации (2026-09-29):

1. **Ввод.** `Command = { type: 'press', button }`, кнопки `forward/back/left/right/dash`; `InputState.held` (зажатые кнопки) и `InputState.look` (yaw/pitch). Клавиатура: WASD и стрелки, `Space` = dash (для фазы 3, пока не используется). `core/input/mouseLook.ts`: Pointer Lock по клику (`unadjustedMovement`, если браузер даёт), `movementX/Y` → yaw/pitch сразу в обработчике события, pitch в пределах `PITCH_LIMIT`. Тач, свайпы, защита жестов, PWA-манифест и мобильные meta — удалить.
2. **Геометрия.** `sim/level/geometry.ts`: `Rect`, `Segment`, `rectWalls()`, ближайшая точка на отрезке. `sim/level/sandbox.ts`: комната `sandbox.ROOM_W × ROOM_D` плюс колонны и внутренняя стена с проёмом — чтобы проверить скольжение, углы и читаемость проёма. Высоты — только данные для рендера.
3. **Движение** (`sim/player.ts`): желаемая скорость из held-кнопок и yaw, диагональ нормализована; скорость стремится к цели с `ACCEL` (есть ввод) или гасится `FRICTION` (нет ввода). Коллизия круг↔отрезки: перемещение делится на подшаги не длиннее `SUBSTEP`, после каждого — выталкивание из стен и удаление составляющей скорости в стену (скольжение). Хранится прошлая позиция для интерполяции рендера.
4. **World:** демо (пипы, сетка, счёт) удаляется; `StepInput = { commands, held, yaw }`; события — через `SimEvent`.
5. **Рендер.** `render/levelMesh.ts`: пол/потолок/стены, нарезанные на сегменты `view.MESH_SEGMENT` (~1 м, нужно для vertexFisheye), плоские цвета в вершинах, шахматка на полу для чувства скорости, `MeshBasicMaterial` + туман, без света. Туман радиальный (по расстоянию, не по глубине) — иначе при широком FOV края светлеют.
6. **Проекции** (`render/camera/`): интерфейс `Projection` (`render`, `resize`, `halfFovH` — порог для rear vision §12). `perspective` — вертикальный FOV из `H_FOV` и аспекта. `cubemap` — `CubeCamera` с гранями `CUBE_FACE_SIZE` + полноэкранный шейдер: пиксель → угол (equidistant / stereographic, `FISHEYE_MAPPING`) → направление → выборка из куба. `vertexFisheye` — патч `project_vertex` всех материалов через `onBeforeCompile`, общий uniform-флаг, без перекомпиляции при переключении. Для fisheye-режимов свой `FISHEYE_H_FOV` (180), чтобы сравнивать каждый режим на его естественном обзоре. Чистая математика — в `fisheyeMath.ts`, с тестами.
7. **Разрешение.** Канвас рендерится в `INTERNAL_SCALE` от окна, растягивается CSS `image-rendering: pixelated`; `MAX_PIXEL_RATIO` = 1.
8. **Отладка.** Выпадающие списки для строковых тюнингов (`OPTIONS` в `tuningLayout.ts`), клавиша `P` при открытом DBG переключает проекцию, оверлей: проекция, скорость, позиция. `__game.input.held/look` — управление без Pointer Lock.
9. **Тесты:** разгон/торможение по тикам из тюнинга, диагональ, направление по yaw, стена не пробивается ни на какой скорости, скольжение вдоль стены, колонна, пауза, математика проекций.
10. **Спайк:** сравнить три режима в Chrome (1920×1080), записать FPS и впечатления в VISUAL.md §3 и сюда; выбор проекции — вместе с пользователем после плейтеста. Потом удалить проигравшие режимы.

## 3. Мувсет: прыжок, рывок, скольжение — в работе

GDD §3, §5. Закоммичено 2026-09-29 (`cab5639`): фазы 1–2, тестовый уровень принят пользователем.

**Первая попытка — рывок вбок (`Space` + `A`/`D`, 7 м, кулдаун) — отклонена плейтестом:** «странно и тухло, особенно только вбок и без прыжка». Код лежит незакоммиченным (`src/sim/dash.ts`, `tests/dash.test.ts`) и удаляется целиком.

**Обсуждение 2026-09-30** (brainstorming, ориентиры Hyper Demon, Neon White, ULTRAKILL):
- Зачем мувсет: увороты и скорость, упор на скорость и поток; «easy to learn, hard to master». Суть игры — увороты и побег, игрок «как рыба в воде».
- Прыжок настоящий, уровни плоские. Вертикальные пещеры — позже.
- Набор «три действия»: прыжок + распрыжка, рывок (главный уворот), скольжение.
- Управление — **только `Space`** по таймингам, как в Hyper Demon; `C`/`Shift` отклонены пользователем, `Ctrl` запрещён (`Ctrl + W`).
- Удара вниз нет (в Hyper Demon его путают с рывком).
- Уменьшенного хитбокса рывка нет; контакт с врагом в 3D, форма врага по высоте — фаза 4.
- Полный дизайн с числами — GDD §5.

План реализации:

1. **Ввод.** `Button 'dash'` → `'jump'`; нажатие — команда `press`, удержание/отпускание — `held.jump`. Рестарт на экране смерти по `press jump`. Подсказка на титуле: `SPACE  JUMP / DASH / SLIDE`.
2. **Тюнинг.** Группы `jump`, `dash`, `slide`, `player.BODY_HEIGHT` — числа из GDD §17; `RANGES` и `TUNE_LAYOUT`.
3. **Симуляция** (`src/sim/move/`, старые `sim/dash.ts` и тест удаляются):
   - `state.ts` — `MoveState`: `y`, `vy`, режим `ground | air | dash | slide`, тики приземления и схода с пола, тик последнего нажатия (буфер), `airDashUsed`, `holdSinceDash`, параметры текущего рывка (старт, направление, скорость) и скольжения (старт).
   - `space.ts` — одна кнопка: по нажатию/удержанию/отпусканию, режиму и таймингам — прыжок (койот, буфер), рывок (по WASD, без WASD — вперёд), скольжение на касании, прыжок из скольжения. Возвращает, что произошло, для событий.
   - `motion.ts` — скорость по режимам: земля (разгон/трение как сейчас + спад скорости выше бега вне окна распрыжки), воздух (руление без разгона сверх текущей скорости, гравитация), рывок (горизонтально, зависание), скольжение (трение, ограниченный поворот, лимит времени, `STOP_SPEED`); потолок `MAX_SPEED`; высота и приземление.

5. **Рендер:** высота камеры = `y` + высота глаз по режиму, в скольжении плавно к `slide.EYE_HEIGHT` за `CAMERA_TIME`.
6. **HUD:** индикатор «рывок доступен», полоска времени скольжения. **Звук:** заглушки на новые события.
7. **Документы:** инвариант CLAUDE.md «высота только в рендере» → «у игрока и врага есть высота, уровень и стены — 2D»; GDD §17 «в коде» для новых групп; VISUAL.md карта кода.
8. **Тесты** (тики из тюнинга): высота и длительность прыжка; койот и буфер; распрыжка сохраняет скорость в окне и теряет вне; рывок — скорость от текущей, горизонтален при любом pitch, один за полёт, зависание, выход 60%, без WASD вперёд; скольжение — только при удержании с рывка, трение, поворот, лимит, `STOP_SPEED`, прыжок при отпускании; стены во всех режимах; высота тела; потолки уровня выше прыжка + рост.
9. **Проверка в браузере** и плейтест пользователя; выводы — сюда.

## 4. Враг — в работе

GDD §11. HUNT / WINDUP / CHARGE / RECOVER, навигация по графу + прямое преследование, оглушение о стену, честный спавн, смерть, экран смерти и рестарт < 2 с. Сначала на тестовом уровне.

Решения 2026-09-30 (с пользователем):
- Числа пересчитаны под бег 15 м/с, мувсет и масштаб 2.5×: радиус 1.2 м, охота 12 м/с, атака с 12–30 м, замах 0.45 с, таран 40 м/с на 45 м; паузы прежние. GDD §11, §17.
- **Вариант A:** враг парит, тело на высоте 1.1–3.3 м; от тарана уходят рывком вбок или скольжением под ним, перепрыгнуть нельзя. Вариант B (вторая атака — низкий бросок, от которого прыгать) — первое расширение.
- Враг красный и туманом не гаснет (сигнальный цвет), но стены его закрывают.

План реализации:

1. **Уровень:** у зон пола — к какой комнате или ребру они относятся; проёмы по рёбрам (точки на обеих комнатах); `locate(level, x, z)` — в какой комнате/коридоре точка; `lineOfSight(walls, a, b, width)` — «толстый луч» (три параллельных луча).
2. **Тюнинг** `enemy`: числа из GDD §17 плюс `HOVER`, `HEIGHT`, `FIRST_LEVEL`, `REPATH_TIME`, `WAYPOINT_RADIUS`.
3. **Симуляция** (`src/sim/enemy.ts`): состояния MATERIALIZE → HUNT → WINDUP → CHARGE → RECOVER / STUNNED. Коллизия со стенами — общая с игроком (`moveAndSlide` с радиусом). HUNT: прямое преследование в той же зоне или при видимости, иначе путь по графу (BFS) через проёмы, пересчёт каждые `REPATH_TIME`. WINDUP: стоп, доворот, фиксация направления в конце. CHARGE: 40 м/с, руление 20°/с, до `CHARGE_MAX_DIST` (→ RECOVER) или удара о стену (→ STUNNED).
4. **Появление** в момент подбора EYE с уровня `FIRST_LEVEL`: комната на расстоянии ≥2 по графу и не на кратчайшем пути EYE→START (если есть), из ближайших — поток RNG `enemy`. Debug-кнопка «spawn enemy».
5. **Контакт** в 3D: круги на плоскости + пересечение тел по высоте (`bodyRange`), не в MATERIALIZE → `kill()`.
